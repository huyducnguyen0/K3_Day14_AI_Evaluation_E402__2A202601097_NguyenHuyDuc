# Complete AI Evaluation Lab Design

## Goal

Turn the starter lab into a submission-ready RAG evaluation project with a tested
evaluation core, a valid 20-case golden dataset, real benchmark artifacts, and
completed written deliverables.

## Design

`template.py` remains the reusable evaluation core.  It will expose the data
models and evaluator APIs exercised by `tests/test_solution.py`; it scores answer
quality with token-overlap heuristics and retrieval quality with recall and
rank-aware average precision.  `evaluate_answers.py` remains an adapter: it joins
the authored gold records to the RAG answer artifact and delegates all scoring to
the core.

The golden dataset will use the provided ten-document Student Services corpus.
It will contain exactly 20 independently answerable cases: 5 easy, 7 medium, 5
hard, and 3 adversarial.  Each record will cite literal evidence from the corpus
and include a concise expected answer.  Adversarial records will evaluate safe
scope handling, injection resistance, and false-premise correction.

The final run sequence is: validate the dataset, generate RAG answers with the
configured OpenAI key, evaluate saved answers, then record the actual aggregate
results and failure analysis in the worksheet and reflection.  If an API key is
not configured, all offline deliverables and automated tests still complete; the
only deferred portion is generation of the live answer artifact.

## Acceptance Criteria

- `pytest tests/ -q` reports 42 passing tests.
- `python validate_golden_dataset.py` reports PASS with all ten documents covered.
- `solution/solution.py` is a complete copy of the final evaluation core.
- `exercises.md` and `reflection.md` contain completed lab responses grounded in
  the generated benchmark artifact.
- When `OPENAI_API_KEY` is available, `artifacts/actual_answers.json` and
  `artifacts/benchmark_results.json` are generated by the supplied scripts.
